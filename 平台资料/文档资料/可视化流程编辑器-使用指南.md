# 可视化流程编辑器 - 使用指南

## 📌 功能概述

可视化流程编辑器是一个创新的UI自动化测试工具，允许通过拖拽流程图的方式创建Playwright测试用例，无需编写代码。

### 核心特性

- ✅ **可视化设计**: 通过拖拽节点创建测试流程
- ✅ **快照集成**: 基于Playwright快照文件加载真实页面结构
- ✅ **元素渲染**: 在页面节点内部直接显示可交互元素
- ✅ **连线定义**: 通过连接元素定义测试步骤和执行顺序
- ✅ **代码生成**: 自动生成可执行的Playwright Python脚本
- ✅ **一键执行**: 直接在平台内执行生成的测试脚本

## 🚀 快速开始

### 1. 访问编辑器

在系统主菜单中，导航至：**手工用例 → 可视化流程编辑器**

访问URL: `http://localhost:3002/manual-testcases/visual-flow`

### 2. 创建第一个测试流程

#### 步骤 1: 添加开始节点

1. 从左侧工具栏拖拽 **"开始"** 节点到画布中央
2. 点击节点，在右侧配置面板设置：
   - **浏览器类型**: `chromium` / `firefox` / `webkit`
   - **初始URL**: 测试网站的URL（如 `https://example.com`）
   - **视口宽度**: `1920` (像素)
   - **视口高度**: `1080` (像素)
   - **Headless模式**: 勾选表示无头模式，不勾选会显示浏览器窗口

#### 步骤 2: 添加页面节点

1. 拖拽 **"页面"** 节点到画布
2. 从开始节点的右侧连接点拖拽连线到页面节点的左侧连接点
3. 点击页面节点，在右侧配置：
   - **页面名称**: 给页面起个有意义的名字（如"登录页"）
   - **快照文件**: 从下拉列表选择Playwright快照文件
4. 点击 **"加载快照"** 按钮

**成功标志**:
- 页面节点内部显示可交互元素列表
- 每个元素右侧显示黄色连接点
- 右侧面板显示元素树结构

#### 步骤 3: 定义执行路径

在页面节点内部连接元素，定义测试步骤：

1. **连接第一步**: 从第一个元素（如用户名输入框）的连接点拖拽到第二个元素
2. **配置操作**: 点击刚创建的连线，在右侧设置：
   - **操作类型**: 选择 `fill`（填充）
   - **操作值**: 输入 `admin@example.com`
3. **连接第二步**: 从第二个元素（如密码输入框）连接到第三个元素
4. **配置操作**:
   - **操作类型**: 选择 `fill`
   - **操作值**: 输入 `password123`
5. **连接第三步**: 从第三个元素连接到登录按钮
6. **配置操作**:
   - **操作类型**: 选择 `click`

**支持的操作类型**:
- `click`: 点击元素
- `fill`: 填充文本（用于输入框）
- `select`: 选择下拉选项
- `hover`: 鼠标悬停
- `dblclick`: 双击

#### 步骤 4: 添加等待操作（可选）

如果需要等待页面加载或其他操作：

1. 拖拽 **"操作"** 节点到画布
2. 连接页面节点到操作节点
3. 配置操作节点：
   - **操作类型**:
     - `sleep`: 等待指定时间（毫秒）
     - `waitForSelector`: 等待元素出现
     - `waitForNavigation`: 等待页面导航
     - `waitForLoadState`: 等待页面加载完成
     - `screenshot`: 截图
     - `custom`: 自定义代码

#### 步骤 5: 添加结束节点

1. 拖拽 **"结束"** 节点到画布
2. 连接最后一个节点到结束节点
3. 可选配置：
   - 勾选 **"生成测试报告"** 会在脚本中添加打印语句

## 📝 生成和执行脚本

### 生成脚本

1. 点击顶部工具栏的 **"生成脚本"** 按钮
2. 查看生成的Playwright Python代码
3. 可以执行以下操作：
   - **复制代码**: 复制到剪贴板
   - **下载脚本**: 保存为`.py`文件
   - **执行测试**: 直接在平台内运行

### 生成的脚本示例

```python
"""
自动生成的Playwright测试脚本
生成时间: 2026-04-14 10:30:00
"""

import asyncio
from playwright.async_api import async_playwright

async def run_test():
    async with async_playwright() as p:
        # 启动浏览器
        browser = await p.chromium.launch(headless=False)
        context = await browser.new_context(
            viewport={'width': 1920, 'height': 1080}
        )
        page = await context.new_page()

        # 访问页面
        await page.goto('https://example.com')
        await page.wait_for_load_state('networkidle')

        # 页面: 登录页
        await page.fill('[data-ref="username"]', 'admin@example.com')
        await page.fill('[data-ref="password"]', 'password123')
        await page.click('button:has-text("登录")')

        # 等待
        await page.wait_for_timeout(2000)

        # 测试完成
        print("测试执行完成")

        # 关闭浏览器
        await browser.close()

if __name__ == "__main__":
    asyncio.run(run_test())
```

### 执行测试

**前置条件**: 确保已安装Playwright

```bash
pip install playwright
python -m playwright install chromium
```

**执行步骤**:
1. 在脚本预览对话框中点击 **"执行测试"**
2. 等待执行完成（最长5分钟）
3. 查看执行结果：
   - ✅ **成功**: 显示标准输出
   - ❌ **失败**: 显示错误信息和堆栈跟踪

## 💾 保存和加载流程图

### 保存流程图

1. 点击顶部工具栏的 **"保存流程图"** 按钮
2. 输入流程图名称（如"用户登录测试"）
3. 选择关联的项目
4. 点击确认

流程图将保存到数据库，包含：
- 所有节点和连线
- 节点配置信息
- 执行路径数据
- 快照文件引用

### 加载流程图

1. 点击顶部工具栏的 **"加载流程图"** 按钮
2. 从列表中选择已保存的流程图
3. 点击加载

画布将恢复到保存时的状态，包括所有节点、连线和配置。

## 🎯 高级用法

### 多页面测试流程

创建跨多个页面的测试场景：

```
开始 → 登录页 → 操作(等待) → 首页 → 操作(等待) → 个人中心 → 结束
```

**关键点**:
- 每个页面节点可以加载不同的快照文件
- 页面间用操作节点连接，添加必要的等待
- 脚本生成时会按拓扑排序确定执行顺序

### 条件分支（未来支持）

当前版本不支持条件分支，所有节点按线性顺序执行。未来版本将支持：
- 判断节点：基于元素状态或文本内容进行分支
- 循环节点：重复执行某些步骤

### 自定义代码插入

通过"操作"节点的"自定义"类型，可以插入原生Playwright代码：

```python
# 自定义操作
await page.evaluate("window.scrollTo(0, document.body.scrollHeight)")
await page.wait_for_timeout(1000)
```

## 📊 元素选择器优先级

系统自动为每个元素生成多个选择器，按优先级排序：

1. **data-ref 选择器** (优先级最高)
   - 格式: `[data-ref="e123"]`
   - 最稳定，不受页面变化影响

2. **Role 选择器**
   - 格式: `button[role="button"]`
   - 语义化，推荐使用

3. **Text 选择器**
   - 格式: `button:has-text("登录")`
   - 直观但可能受文本变化影响

4. **Tag 选择器** (优先级最低)
   - 格式: `button`
   - 通用但不够精确

生成脚本时，系统会自动选择优先级最高的可用选择器。

## 🔧 故障排查

### 快照加载失败

**症状**: 点击"加载快照"后显示错误消息

**可能原因**:
- 快照文件不存在或已被删除
- 快照文件格式错误（不是有效的YAML）
- 权限不足

**解决方法**:
1. 检查 `playwright_snapshot/` 目录中是否存在快照文件
2. 尝试重新生成快照文件
3. 检查文件权限

### 脚本生成为空

**症状**: 生成的脚本只有框架代码，没有实际操作

**可能原因**:
- 页面节点未加载快照
- 未创建元素间连线
- 未配置执行路径

**解决方法**:
1. 确保每个页面节点都已加载快照
2. 在页面节点内部创建元素间连线
3. 检查右侧配置面板的"执行路径"列表是否有内容

### 脚本执行失败

**症状**: 执行测试时报错

**常见错误**:

1. **ModuleNotFoundError: No module named 'playwright'**
   ```bash
   pip install playwright
   python -m playwright install chromium
   ```

2. **TimeoutError: Timeout 30000ms exceeded**
   - 增加等待时间
   - 检查URL是否可访问
   - 检查元素选择器是否正确

3. **元素未找到**
   - 验证快照文件是否与当前页面匹配
   - 尝试使用更通用的选择器（如文本选择器）
   - 添加`waitForSelector`操作节点等待元素出现

## 📚 最佳实践

### 1. 命名规范

- **流程图名称**: 使用描述性名称，如"用户登录流程"、"订单创建测试"
- **页面节点**: 使用页面的实际名称，如"登录页"、"商品详情页"
- **操作节点**: 简要说明操作目的，如"等待页面加载"、"截图验证"

### 2. 模块化设计

将大型测试拆分为多个小流程图：
- 登录流程
- 数据准备流程
- 核心业务流程
- 清理流程

### 3. 合理使用等待

在以下情况添加等待操作：
- 页面跳转后
- 表单提交后
- Ajax请求后
- 动画效果期间

避免过度等待，影响执行效率。

### 4. 定期更新快照

当页面结构变化时，及时重新生成快照文件：

```bash
# 使用Playwright生成新快照
python -m playwright codegen <URL> --save-storage=state.json
```

### 5. 版本控制

将流程图和快照文件纳入版本控制：
- 流程图导出为JSON格式
- 快照文件存储在`playwright_snapshot/`目录
- 使用Git跟踪变更

### 常见问题

**Q: 可以测试移动端页面吗？**

A: 可以。在开始节点配置中设置移动端视口大小，如375x667（iPhone尺寸）。

**Q: 支持哪些浏览器？**

A: 支持Playwright的所有浏览器：Chromium、Firefox、WebKit（Safari）。

**Q: 可以录制真实操作生成流程图吗？**

A: 当前版本不支持录制功能，需要手动创建流程图。未来版本将支持录制模式。

**Q: 如何处理动态生成的元素？**

A: 使用`waitForSelector`操作节点等待元素出现，或使用文本选择器（更灵活）。

**Q: 可以集成到CI/CD流程吗？**

A: 可以。生成的Python脚本可以直接在CI/CD环境中执行，配合pytest框架使用。

## 🎓 示例：完整的登录测试流程

### 流程图结构

```
[开始节点]
   ↓
[页面节点: 登录页]
   内部连线:
   1. 用户名输入框 → 密码输入框 (fill: "admin")
   2. 密码输入框 → 登录按钮 (fill: "password123")
   3. 登录按钮 → (下一节点) (click)
   ↓
[操作节点: 等待2秒]
   ↓
[页面节点: 首页]
   内部连线:
   1. 用户头像 → (验证登录成功) (hover)
   ↓
[操作节点: 截图]
   ↓
[结束节点]
```

### 配置详情

**开始节点**:
- 浏览器: chromium
- URL: https://your-app.com/login
- 视口: 1920x1080
- Headless: false

**页面节点 - 登录页**:
- 页面名称: 登录页
- 快照文件: login-page-snapshot.yml
- 执行路径:
  1. textbox[placeholder="用户名"] → textbox[placeholder="密码"] | fill: "admin"
  2. textbox[placeholder="密码"] → button:has-text("登录") | fill: "password123"
  3. button:has-text("登录") → (下一节点) | click

**操作节点 - 等待**:
- 操作类型: sleep
- 超时: 2000ms

**页面节点 - 首页**:
- 页面名称: 首页
- 快照文件: home-page-snapshot.yml
- 执行路径:
  1. img[alt="用户头像"] → (验证) | hover

**操作节点 - 截图**:
- 操作类型: screenshot
- 文件路径: login-success.png

### 生成的脚本

脚本将包含完整的登录流程，可直接执行或集成到测试套件中。
